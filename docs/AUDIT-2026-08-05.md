# HazardOS — application audit, 2026-08-05

Measured, not estimated. Every number below came from running something against
the current tree or the production database; where a heuristic could not be
trusted it is called out rather than reported as fact.

---

## What this audit got wrong

Three of seven findings (#6 rate limiting, #7 unbounded queries, and an early
draft claim that every `/api/v1/*` route was unauthenticated) were **false**, and
all three failed the same way: a grep or a fixed line-window used as a proxy for
behaviour.

The split is clean, and worth remembering before the next audit:

| Method | Findings | Verdict |
|--------|----------|---------|
| Direct measurement — bundle bytes in a browser, `npm audit`, `wc -l`, config values, catalog queries | #1, #2, #3, #4, #5, #8, #9 | all real |
| Grep / line-window heuristics over source | #6, #7, the v1 auth claim | all false |

Every heuristic finding was wrong, and wrong in the same direction: the code was
better than the measurement of it. Safety in this codebase usually lives in a
wrapper (`createApiHandler` applies rate limiting before the route body runs) or
a few lines further down than a fixed window reaches. Measure the behaviour, or
read the wrapper — do not count occurrences.

The application is in good shape on the things that are usually bad: no `any`,
no hardcoded secrets, no `dangerouslySetInnerHTML`, RLS on every table, and every
API route authenticated. The weak areas are **bundle weight**, **unit-test
coverage**, and **route-level error/loading UX**, plus two dependency

## HIGH

### 1. Initial JS is 498 KB gzipped, against a 300 KB budget

`vendors-*.js` is 1,372 KB raw / **498 KB gzipped**, and it is an `initial`
chunk, so every user downloads it before the app is usable. `web/performance.md`
sets 300 KB gzipped for an app page. This is 66% over.

Total client JS on disk is 3.4 MB across all chunks.

The heavy libraries are already handled correctly — recharts (388 KB), PDF,
Excel and the AI SDKs are all in `async` cache groups and lazy-loaded. The
problem is the `vendor` group itself: `chunks: 'initial'` with `minChunks: 2`
sweeps everything used twice into one blocking chunk.

Worth attacking first because it affects every user on every visit, and mobile
field staff on poor connections most of all.

### 2. Two high-severity dependency vulnerabilities in the production tree

| Package | Via | Issue |
|---|---|---|
| `brace-expansion` 5.0.8 | `@serwist/next` | DoS via unbounded intermediate arrays, bypassing the earlier CVE mitigation |
| `fast-uri` 3.1.4 | `@sentry/nextjs` → webpack → schema-utils → ajv | Host confusion via backslash authority introducer |

Both are **build tooling** pulled into the production tree because their parents
are runtime dependencies. Neither sits on a request path, so real exposure is
low — but `brace-expansion` is notable: a previous fix moved to the version now
flagged, so the advisory has caught up with the mitigation.

### 3. Unit coverage thresholds are less than half the stated standard

`vitest.config.ts` enforces lines 39%, statements 37%, functions 35%,
branches 29%. `common/testing.md` requires 80% minimum.

This matters less than it looks, because the integration (77) and E2E (26)
suites cover the paths that actually break — RLS, tenant isolation, the API,
offline behaviour. But branch coverage at 29% means most conditional logic has
never been executed by a test.

## MEDIUM

### 4. Almost no route-level error or loading UI

Across roughly 100 routes there is **one `error.tsx` and one `loading.tsx`**.

Practically: most route failures bubble to the nearest boundary rather than
showing something useful in place, and most navigations show nothing while data
loads. There are 21 component-level error boundaries, so this is not unhandled —
it is unpolished, and it is the kind of thing a customer notices immediately.

### 6. ~~Rate limiting covers 25 of 236 API routes~~ — RETRACTED 2026-08-06

**This finding was wrong.** It counted explicit `applyUnifiedRateLimit` calls in
route files and missed that the handler wrappers apply it by default:
`createApiHandler` and `createPublicApiHandler` both default to
`rateLimit = 'general'` and call the limiter unconditionally before auth.

Actual coverage is **232 of 236**. The four exceptions are the cron endpoints,
and all four verify a `CRON_SECRET`, so they are not publicly reachable.

Worth recording *why* this was wrong, because the same mistake produced a second
false finding in the first draft of this audit (every `/api/v1/*` route reported
as unauthenticated, when they use `withApiKeyAuth`). Grepping route files for a
mechanism systematically under-counts protection in a wrapper-based
architecture. Check what the wrapper does before counting what the route does.

### 7. ~~444 `.select()` calls without an explicit limit~~ — RETRACTED 2026-08-06

**This finding was wrong.** Narrowing 444 to 67 "potentially unbounded", then
reading the 67, found no unbounded list reads at all:

- the list endpoints already paginate — `JobsService.getJobs` defaults to 50 and
  `PipelineService.getOpportunities` to 100, both via `.range()`
- several are **aggregations** (`select('commission_amount')` summed for
  commission totals). Adding `.limit()` to those would not have improved
  anything, it would have produced **silently wrong money**
- the rest are single-row `getById` fetches, org-scoped config tables of a few
  rows, or matview reads already bounded by a date range

The heuristic failed because it read a fixed window of lines after `.select(`.
In this codebase a select frequently spans a dozen lines of embeds before
reaching its `.eq('id', …)`, `.single()` or `.range()`.

## LOW

### 8. Accessibility: 27 known gaps

- **21 bare `<Label>`** — date pickers (want `aria-label` on the popover button),
  checkbox/radio groups (want `fieldset`/`legend`), and section headings that
  should not be `<Label>` at all. Left deliberately; a mechanical fix would
  produce markup that validates and misleads.
- **5 of 69 icon-only buttons** with no accessible name, in
  `crm/companies/[id]`, `crm/jobs/[id]`, `crm/opportunities/[id]`,
  `settings/api/new`, and `surveys/mobile/sections/hazards-section`.
- **1 `<img>` without `alt`** in `site-surveys/[id]/sections/media-section.tsx`.

366 label associations are now correct with zero broken, which was not true
yesterday.

### 9. 54 outdated direct dependencies

Mostly minor. The outlier is `@anthropic-ai/sdk` at 0.72.1 against 0.115.0 —
dozens of releases behind, on a fast-moving SDK.
